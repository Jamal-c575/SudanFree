3. BEHAVIORAL CHANGES
================================================================================

sendWhatsAppOTP() FUNCTION:
────────────────────────────────────────────────────────────────────────────
OLD:
  1. Validate phone
  2. Generate OTP
  3. Store in Firestore
  4. If dev mode: Store debug copy, return debugOtp
  
NEW:
  1. Validate phone
  2. Check rate limit → Block if exceeded
  3. Generate OTP
  4. Send via Twilio (if prod + credentials)
  5. Store in Firestore with delivery status
  6. If dev mode: Store debug copy, return debugOtp + note
  7. Log audit event (OTP_SENT or OTP_REQUEST_BLOCKED)
  
RATE LIMIT:
  - Max 3 requests per phone per 10 minutes
  - Error code: "resource-exhausted"
  - Error message: "Too many OTP requests. Please try again in X minutes."


verifyWhatsAppOTP() FUNCTION:
────────────────────────────────────────────────────────────────────────────
OLD:
  1. Find OTP
  2. Validate code
  3. Mark used
  4. Return success
  
NEW:
  1. Validate inputs
  2. Check brute-force limit → Block if exceeded
  3. Find OTP
  4. Validate code → Log failed attempt if wrong
  5. Mark used
  6. Clear brute-force counter
  7. Log audit event (OTP_VERIFIED or OTP_VERIFY_FAILED)
  8. Return success
  
BRUTE-FORCE PROTECTION:
  - Max 5 failed attempts per phone per 15 minutes
  - Counter reset on successful verification
  - Error code: "permission-denied"
  - Error message: "Too many failed attempts. Request a new OTP."


isAdmin() CHECK:
────────────────────────────────────────────────────────────────────────────
OLD:
  - Reads from Firestore on every check
  - 100ms latency per check
  - 1000+ reads per second at scale
  
NEW:
  - Reads from Auth token (cached locally)
  - <1ms latency per check
  - 0 Firestore reads
  - Synced automatically when role changes

4. NEW FIRESTORE COLLECTIONS
================================================================================

audit_logs
──────────────────────────────────────────────────────────────────────────────
Purpose: Store all security events for compliance
Documents: ~50 per hour (depends on user activity)
Retention: Indefinite (recommended: archive after 1 year)
Access: Admin-only read, Cloud Functions write-only

Schema:
{
  action: string,           // OTP_SENT, OTP_VERIFIED, etc.
  userId: string | null,
  phoneNumber: string | null,
  status: string,           // success, failed, blocked, error
  errorMessage: string | null,
  timestamp: Timestamp,
  ipAddress: string | null,
  adminId: string | null,
  details: object           // Additional metadata
}


_rate_limits
──────────────────────────────────────────────────────────────────────────────
Purpose: Track OTP request rate limiting
Documents: 1 per phone number (with activity)
Retention: Auto-cleanup recommended (older than 30 days)
Access: Cloud Functions only

Schema:
{
  count: number,            // Current request count
  resetAt: Timestamp,       // When window resets
  createdAt: Timestamp
}

Document ID Format: otp_send_+249912345678


_brute_force_attempts
──────────────────────────────────────────────────────────────────────────────
Purpose: Track failed OTP verification attempts
Documents: 1 per phone number (with failures)
Retention: Auto-cleanup recommended (older than 30 days)
Access: Cloud Functions only

Schema:
{
  count: number,            // Failed attempt count
  resetAt: Timestamp,       // When window resets
  createdAt: Timestamp
}

Document ID Format: otp_verify_+249912345678
